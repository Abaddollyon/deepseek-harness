# Agent Note：移除 PSReadLine 回显，而不是剥离它

Status: proposed

[English](2026-08-25-pwsh-echo-free-capture.md) | 中文

## 问题

`tool-pwsh-persistent` 驱动一个真实 PTY：提交命令并回读屏幕。PowerShell 的行编辑器 PSReadLine 会把提交的输入重新渲染到该流中，因此屏幕上带有两份包装器——一份是输入回显，一份是真实输出。捕获以标记为锚点，随后通过匹配包装器源文本剥离回显。

该剥离仅在回显的包装器占据一个物理行时成立，这正是 `wrapCommand` 声明的不变量：“把包装器保持在一个物理行上：PSReadLine 会渲染回显的输入，而换行的行会切断提取所要剥离的回显。”

该不变量并不成立。对一条短命令，包装器长 412 个字符，而 `terminal-bash` 以其配置的 160 列打开 PTY，于是回显跨越三个物理行。终端插入的换行破坏了剥离，锚点落在回显内部而非输出上，捕获因此一无所获。CI 直接呈现了结果：某断言在本应是输出的位置收到了命令文本 `'"console=" + [Console]::OutputEncoding…'`。

加宽终端无法解决问题，因为模型自己的命令被嵌入包装器：任何固定宽度都会被足够长的命令超出。当前行为并非“宽度略小”，而是一个无法保证的上界。

该故障通过三层遮蔽保持隐形：真实 shell 用例在缺少 `pwsh` 的机器上跳过，而这正是通常运行该套件的机器；上游在自建 Windows runner 上执行它们；而本 fork 在加入托管门禁之前根本没有 CI 在运行。Linux 路径似乎从未工作过。另一处修复已使空捕获不再被报告为截断输出，因此当前故障是诚实的超时而非错误结果，但命令仍未执行。

## 提案

在 shell 初始化时从会话中移除 PSReadLine，使其不产生回显。捕获随后只需读取自有标记之间的文本，无需剥离，单物理行不变量连同守护它的机制一并消失：包装器源剥离、回退路径中的部分回显处理，以及使长命令不安全的宽度敏感性。

包 README 目前把回显记为不可避免：“输入回显不可避免：PowerShell 的 PSReadLine 会把提交的输入重新渲染到终端流中，且不存在 `stty -echo` 的等价物。”移除该模块就是这一等价物。PSReadLine 是交互式行编辑器；程序化 shell 不需要命令行编辑、历史搜索或语法高亮。

## 备选方案

**为 pwsh 会话加宽 PTY。** 否决。它只对短命令恢复不变量。由于模型命令嵌入在包装器中，足够长的命令仍会换行，把稳定失败变成间歇失败——这更糟，因为它会通过促成本次改动的那些测试。

**缩短包装器。** 基于同样理由否决：只争取余量，不建立上界。

**让提取容忍换行的回显。** 作为主路线否决。它把终端宽度推理引入一个当前无需它的解析器，并保留本提案要移除的回显处理层。仅在 PSReadLine 无法移除时才值得重新考虑。

**将该工具限定为 Windows，其他平台跳过。** 否决：README 已记载支持 POSIX pwsh，跳过等于把缺陷固化为平台边界。

## 验收标准

在下列条件按序成立之前，本提案未获证实：

1. 移除 PSReadLine 的会话能够启动并执行命令，且读取流中不含提交输入的回显。
2. `packages/shell/tool-pwsh-persistent/tests/tools.spec.ts` 中基于 mock 的套件在回显处理路径移除后通过；或每个被删除的用例连同其理由一并记录删除。
3. 真实 shell 用例——`tests/loader-composition.spec.ts` 与 `packages/terminal/terminal-bash/tests/local.spec.ts`——在存在 `pwsh` 时通过，包括 UTF-8 编码用例。
4. 托管的 fork CI 门禁通过，因为它正是暴露该缺陷的环境。仅本地通过不构成证据：这些用例在缺少 `pwsh` 时会跳过。

## 风险

本提案建立在一个尚未测量的假设之上：移除 PSReadLine 确实能抑制回显。若 PowerShell 在没有它的情况下仍会渲染提交的输入，则前提不成立，退路是让提取容忍换行的回显，从而保留本提案原本要移除的那一层。

三个未知项必须通过测量而非判断来确定。`Remove-Module PSReadLine` 是否足够，或必须在不加载它的情况下启动 shell。就绪标记是否仍然存在——该包已记载模型重定义 `prompt` 会移除它并使 shell 落到更慢的静默层。`terminal-bash` 的 pwsh 方言是否自行进行 PSReadLine 设置而需同步调整。

移除回显处理路径会删除其测试。每一次删除都是一项主张：该情形不再可能发生。若某用例因不便而非不可能被删除，就会掩盖当前测试本可捕获的回归。

该改动会改变一个已发布工具在 Windows 上的运行时行为——那里该路径当前可用——而其动因来自 Linux——那里不可用。本地没有 Windows 覆盖，上游的自建 runner 对本 fork 不可用，因此合并前无法观察到 Windows 回归。

## 影响

PowerShell 支持将在 README 已声称的范围内真正工作，长命令不再是隐藏的宽度风险。该包将携带更少而非更多代码，一条已记载的限制将被撤销而非绕过。托管 CI 门禁将凭证据转绿，而非依靠排除。
