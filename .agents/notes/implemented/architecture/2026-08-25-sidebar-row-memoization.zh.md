# Agent Note：侧边栏会话行记忆化

Status: implemented

[English](2026-08-25-sidebar-row-memoization.md) | 中文

> 范围：packages/client/ui-workspace/src/client/rows/Rows.tsx 中工作区浏览器的顶层会话行。

## 问题

会话列表重新发布时，树派生会创建新的行对象，即使会话的可见事实没有变化。1,001 个会话的侧边栏因此重建行子树，却没有产生 DOM 变更。

在活动 Agent Note 中搜索后，没有找到覆盖此侧边栏渲染机制的既有记录。运行时服务单独提供的逐行身份复用是前置条件，而不是被本文取代的决定。

## 决策

SessionNodeItem 使用 React memo，并比较会话行实际显示的标量事实：会话 id、标题、未命名冲突序号、空白状态、等待交互、运行状态、运行中的子代理数量、完成状态、更新时间、当前选择、平面/自动折叠保留/用户置顶模式、翻译函数以及相对时间的显示单位和数值。这些字段覆盖 SessionNodeItemView 的所有可见结果。

非活动拖拽忽略命令函数身份，因为命令按会话 id 定位，行事实不变就意味着命令目标不变。活动拖拽保持对象身份敏感，以便拖拽期间刷新提交闭包。相对时间按显示桶比较而不是比较原始时钟毫秒；只有显示标签变化时才刷新行。

## 后果

等价的列表重新发布不会重建未变化的行；标题、运行状态、交互等待、完成提醒、置顶、折叠组保留行、选择、语言、冲突标签和时间标签变化仍会刷新。活动拖拽保留当前树闭包。比较器只存在于展示行，不增加组件订阅。

## 备选方案

| 放弃的方案 | 原因 |
|---|---|
| React 默认 memo 比较 | 树派生会重建行对象，身份不够稳定。 |
| 只比较会话 id | 可能丢失运行、标题、置顶、选择、折叠保留行和状态更新。 |
| 比较原始时间值 | 即使显示标签不变，时钟毫秒也会使优化失效。 |
| 忽略活动拖拽身份 | 拖拽行可能保留过期的重排提交闭包。 |
