# Agent Note: A long conversation costs what is on screen

Status: implemented

[English](2026-08-20-chat-virtualization-and-selection-confinement.md) | 中文

## 问题

聊天视图中的三项成本随对话而非视口扩大。

`ChatView` 为每个节点挂载一个席位。因此，拥有许多子代理的长轨迹会保留数千个存活的 React 子树，并且每次更新都会协调所有子树。

选择状态在 `ChatView` 中读取，并作为 prop 传递到每个席位，因此选择一个工具调用会重新渲染整个对话，只为改变一行的外观。

详情面板通过 `findToolCall` 解析调用，后者递归遍历每个根和每个子调用直到匹配——这在每次选择交互中都是一次 O(all calls) 遍历。

## 决策

**超过阈值时窗口化流。** `ChatView` 在超过 500 行后以 12 行 overscan、160px 估算值和 16px 间隙进行虚拟化，挂载可见窗口加 overscan。此次变更保留底部跟随、前插和滚动恢复：激活和恢复是显式步骤，展开会固定已展开行，并捕获语义锚点，因此恢复会落在相同的对话位置而非相同的像素偏移。热滚动通过测量偏移上的二分搜索解析行——代码在搜索位置保留了此选择的理由。

**将选择限制在拥有它的两行。** 每个记忆化的 `ChatNodeSeat` 运行自己的选择器，该选择器只为其索引的根返回 callId。一次选择变更会重新渲染旧所有者和新所有者；其余所有内容保持其 memo。

**索引调用而非遍历调用。** `MutableChatNodeStore` 维护一个 `toolCalls` map 和一个反向 `toolCallIdsByNodeKey` map，在节点变更时使用带 `Set` 循环保护的迭代方式更新，详情面板通过 O(1) 查找辅助函数解析。

## 备选方案

**限制渲染的历史而非窗口化它。** 拒绝：上限会删除可达内容，而对话就是产品。窗口化保持每一行可寻址，同时只为可见行付费。

**在前插后按像素偏移恢复滚动。** 拒绝：前插会改变视口上方的每个偏移，因此像素恢复会落在任意位置。捕获语义锚点并恢复到它，才能使滚动期间的前插可存活，并且测试断言锚点与虚拟化前扫描生成的内容匹配。

**将选择保留在 `ChatView` 中，并在席位上对其记忆化。** 拒绝：prop 仍会为每个席位改变，因此每个 memo 比较器都会运行，并且每个席位仍会重新渲染。选择器必须存在于席位内，扇出才能真正停止。

**在每个快照上重建调用索引。** 拒绝：这会将每次交互的遍历转换为每次更新的遍历，对于流式对话而言更糟。

## 影响

有效虚拟化阈值高于 500 行；恢复已保存滚动位置的挂载会刻意避免虚拟化，以使恢复精确。固定和锚定行按设计可能在 overscan 窗口外渲染。索引将一次子树遍历移至每个发生变更的工具根，而非每次查找，这一权衡使选择成为 O(1)。未使用可选索引能力构建的存储会从查找辅助函数返回 `undefined`，因此消费者会回退而非失败。组装后的浏览器输出会改变，这就是它与 web-replay 快照刷新一同落地的原因。
