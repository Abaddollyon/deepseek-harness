# Agent Note: Deriving a trajectory by advancing it, not rebuilding it

Status: implemented

[English](2026-08-20-trajectory-incremental-derivation.md) | 中文

## 问题

Trajectory 在每个事件上重新计算其整个管道。快照构建器重建所有记录并重新排序；布局重新计算每个跨度；工具树重新投影每个节点；时间线为每条记录创建一个 DOM span；虚拟行表重建其行和组。

对于实时会话，这是最差的形式：输入在尾部单调增长，而每次追加都会重新派生不可能已改变的前缀。

## 决策

**分段维护快照并单调追加。** 构建器对每项操作分类，并以位掩码跟踪受影响的段，在更新间保留 map 和索引。单调追加无需排序即可扩展顺序；只有结构性变更才回退为完全重建。操作未触及的段保留其身份，因此下游记忆化得以保持。

**接受一个布局前缀。** 布局将其缓存保存在 WeakMaps 中，并记录已接受前缀边界。快速路径按身份验证前缀，修补活跃助手和工具结果跨度，并扩展已接受索引——因此流式轮次触及其自身尾部而非时间线。

**只重新投影工具树中的祖先。** 工具定义持有调用、子项、父项和投影 map，仅使祖先失效，在 source-plus-interruption 键下缓存每个投影，并通过深度 256 的循环保护来限制遍历。

**按像素分桶时间线。** 跨度被分组到一个 `lane:column` map 中，因此渲染的 DOM 由视口像素宽度而非记录数约束；详情为指针下的单个跨度计算，并在 WeakMap 中缓存。

**保持表格尾部追加稳定。** 虚拟行缓存修补最终行及其后缀，在一个显式资格测试下保留并重新分组后缀，并且只在前插或重排序时重建。

## 备选方案

**按事件窗口身份记忆化整个快照。** 拒绝：窗口在每次追加时都会改变，因此 memo 恰好在关键工作负载期间从不命中。

**在每次追加后排序。** 拒绝：追加按 seq 顺序到达，因此排序可被证明是不必要的；构建器断言单调性，并在不成立时回退为重建，而非为安全起见支付排序成本。

**限制时间线渲染的跨度。** 拒绝：上限会使时间线歪曲发生过的事情。像素分桶渲染每条记录的贡献，同时将 DOM 约束为屏幕实际可区分的内容。

**在任何变更时使整个工具投影失效。** 拒绝：嵌套子代理树正是此视图存在的场景，而整棵树失效会使其成本在深度 × 更新上呈二次方。

## 影响

每个阶段现在都会推进而非重建，但这些界限是诚实的而非绝对的，且值得说明这些注意事项，因为后来的读者否则会假定交付内容超过实际：即使在快速路径上，布局的前缀验证仍为 O(prefix)；时间线仍遍历可见跨度，只是其 DOM 受像素约束；表格的尾部路径会重建全局索引，因此不声称严格的 O(suffix) 总复杂度。结构性快照变更——任何非单调追加的情况——仍会采用完全重建，这才是正确的下限而非缺口。

工具投影缓存由 source 加中断状态键控，因此中断调用会重新投影，而非提供过时的已稳定形态。256 的遍历边界是针对畸形树的保护，而非支持的深度。
