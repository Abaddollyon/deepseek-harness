# Agent Note: 自动发现提供方模型

Status: implemented

[English](2026-09-04-automatic-model-discovery.md) | 中文

## 问题

提供方发布模型可能早于已安装 pi-ai 目录的更新。静态配置因此会让 LLM（大语言模型）服务的全部消费方看不到新模型，而独立的选择器目录又可能显示请求发送时无法解析的模型。

## 决策

[pi-ai 适配器](../../../../packages/llm/llm-pi-ai/README.zh.md)负责显式启用的认证发现操作和共享不可变有效目录。显式模型条目和覆盖项优先于规范化实时元数据，后者优先于已安装容量和已公布能力；同一 id 的已安装模型仍提供协议兼容性。未知 id 使用配置路由的协议与保守容量／模态默认值。发现操作既不编辑设置，也不选择模型。

每条路由拥有一次刷新、取消控制器、定时器以及按配置／凭据限定的元数据缓存。启动时先恢复可用磁盘元数据，再执行网络发现。凭据通知阻止陈旧请求发布；刷新自身串行 `Models.getAuth` 操作中的 OAuth 轮换会继续使用新授权。其他账户变更仍会使请求失效。元数据提交后，发布操作替换适配器注册，复用 `llm/adapters-updated` 及其隔离观察方错误的分发机制。已捕获请求快照保持不可变。dispose（资源释放）会等待所有待处理工作。

Codex 元数据使用公开官方 npm 包端点公布的当前稳定版本进行协商。公开请求不携带提供方认证、不允许重定向，并且只消耗刷新期限中的有限部分。查询失败时可继续使用已缓存的成功版本。元数据协商不改变 pi-ai 执行标头，也不证明新公布模型的兼容性。只有允许的规范化字段会被保留；提供方提示词、指令和未知字段均被丢弃。隐藏／内部以及显式不受支持的 Codex 回复行不会被采纳。

## 考虑过的替代方案

**刷新时重写模型配置。** 不采用，因为发现操作会覆盖显式选择，并将临时提供方回复变成用户设置。

**维护选择器专用目录。** 不采用，因为聊天、委派、自动化和远程配置必须通过同一请求发送服务解析模型。

**永久固定 Codex 发现版本。** 不采用，因为服务端版本过滤可能在认证成功时仍隐藏新模型。公开版本协商使发现结果保持更新，代价是需要单独验证提供方执行能力。

## 后果

离线缓存和逐路由失败隔离保留可用性。元数据不是模型执行 canary；未知协议行为仍需通过无害的真实提供方请求验证。已安装和显式模型仍是有用的回退项，未知推理支持保持保守。可选缓存具有版本，仅属主可访问，不存储凭据或远程指令正文。针对性测试覆盖真实 Loader 组合、可选模型与可发送模型一致性、覆盖项、OAuth 刷新、并发合并、取消、周期任务、陈旧账户请求隔离、离线恢复、协议分页／限制和秘密信息剔除。
