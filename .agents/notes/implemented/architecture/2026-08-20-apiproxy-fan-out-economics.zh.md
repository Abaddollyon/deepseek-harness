# Agent Note: Fan-out economics for the session gateway

Status: implemented

[English](2026-08-20-apiproxy-fan-out-economics.md) | 中文

## 问题

每个已打开的事件流都会安装自己的 `session/event` 监听器，而每个监听器都为同一事件重复计算相同的工作：解析工具渲染视图、构建帧、生成 rpcId，并交给随后由下行链路 JSON 编码的队列。对于 S 个订阅者，主机为一个会话事件支付 S× 的投影和 S× 的编码成本——在流式传输期间，每个块一次。

队列本身是一个通过 `shift()` 排空的数组。在任何积压情况下——多个会话向一个每次等待完成只写入一帧的 socket 流式传输——排空会退化为二次方复杂度，而且没有任何机制会丢弃已经被后续帧置为无关的帧：一个轮次结束后，其已排队的块帧仍会被完整交付。

`session.list` 每次调用都从会话事件计算每一行，包括一次向后扫描日志的预设解析，因此列表成本随总历史增长，而非随行数增长。

`history` 为回答一个页面而物化完整存储日志，子代理目录则通过为每个根遍历所有后代链来重新计算每个分支的运行计数。

## 决策

**一个监听器，一次计算，一个编码帧。** 网关安装单个进程范围的 `session/event` 监听器；渲染视图、帧、其 rpcId 和其编码字节每个事件只生成一次，并由所有订阅者共享。用于结果视图配对的打开调用表同样是进程范围的，受最大存活轮次约束，并在 `turn/end` 时清除。

**可遗忘被取代帧的环形队列。** `FrameQueue` 维护 `buffer` 和 `head` 索引，并在 `head * 2 >= buffer.length` 时压缩，以提供摊销 O(1) 的取出。可选的 `FrameQueueCoalescer` 为每一帧声明 `supersedingKey` 和 `supersededKey`；其 `supersededKey` 与到达帧的 `supersedingKey` 匹配的已排队帧会被替换为空洞。这使得轮次结束时能够丢弃仍排在其后的块帧，并使无所有者任务的扇出成为一帧而非每会话一帧。

**来自投影的行，预设记忆化。** `sessionListFields` 和 `summarize` 接受已投影的元数据和已解析的预设，而 `presetForSession` 在由其解析时的 seq 键控的 `WeakMap<Session, { seq, value }>` 中记忆化向后日志扫描，因此一行仅在日志确实向前移动后才会重新计算。

**分离的历史与冷快照。** `history` 通过协调器的 `readTail` 读取，响应携带一个 `{ kind: 'detached' }` 块——头部、事件、可选投影——因此没有调用者持有实时日志。`coldSnapshot` 使用 `asOfSeq` 边界响应，子代理目录在一次后序遍历中计算分支计数，而非为每个根遍历每条链。

## 备选方案

**在第一个订阅者请求时惰性缓存编码帧。** 拒绝：帧在已知订阅者集合的发射路径上生成，因此惰性化没有收益，反而在帧飞行期间增加了一个需要推理的状态。

**在压力下通过丢弃最旧帧来限制队列。** 拒绝：被丢弃的 `session/event` 帧会在客户端窗口中留下一个只有完全重新同步才能修复的空洞。合并恰好丢弃被后续帧置为无关的帧，这是客户端可以依赖的语义规则，而不是其无法依赖的压力启发式策略。

**将 `session.list` 分页纳入此变更。** 因范围而拒绝：分页是一个线协议变更，必须与客户端列表窗口化一起落地，并单独跟踪。记忆化使每次调用的成本不再取决于历史大小，无需移动边界。

## 影响

每事件主机成本现在独立于打开流数量；队列为摊销 O(1)，并会清除被取代的帧。接收合并流的客户端在轮次结束后看到的中间块帧更少——仅表现为转录更早稳定，因为持久日志未受影响。预设备忘录按日志 seq 键控，因此不追加的变更无法使其失效；每个当前变更都会追加。`history` 响应是分离值，这使得响应能够像任何其他帧一样仅编码一次并共享。
