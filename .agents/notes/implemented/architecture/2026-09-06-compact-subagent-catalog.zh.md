# Agent Note: 紧凑的子代理目录

Status: implemented

[English](2026-09-06-compact-subagent-catalog.md) | 中文

## 问题

长时间使用的会话会积累很多未运行的子代理。双行布局和创建顺序把正在运行的任务推到历史记录下方，而点击分支会离开用户想查看的层级。

## 决策

[子代理目录](../../../../packages/client/ui-subagent/README.zh.md) 将正在运行的代理以及含有运行中后代的祖先排在未运行的同级项前面，各分区内保留来源顺序。每层把未运行的同级项收进带计数的可展开分组，但当前会话始终可见。重新打开菜单时历史记录再次折叠。展开后的未运行行在单行内显示名称、token 和活跃轮次耗时；完整的 mode 和活动状态保留在提示与无障碍名称中。未运行不代表成功完成。

点击分支或按 Enter、Space 会通过现有的延迟目录观察机制展开或收起子项。方向键和展开按钮保留树形导航行为。独立的“打开”按钮进入分支会话；叶节点直接打开。各层保留真实的父级地址，并在用户请求前保持收起。

## 考虑过的替代方案

**在 Vesper 插件中替换目录。** 这会复制原生导航、延迟加载与无障碍行为。由原生所有者提供此布局无需第二套目录实现。

**把全部未运行的同级项显示为紧凑行。** 即使使用单行，数百个代理仍会占满目录。折叠历史记录使当前工作保持可见，同时保留每条记录的访问入口。

**立即平铺全部后代。** 这会丢失工作流祖先关系，并要求加载用户尚未展开的分支。紧凑的同级行保留层级，无需预先加载整棵树。

## 影响

可滚动菜单能容纳更多历史代理，活跃分支仍然容易找到。打开分支会话使用明确的“打开”操作。组件回归测试覆盖含 114 个代理的目录、恢复运行、排序、紧凑布局和键盘导航；持久化子代理浏览器场景检查分支展开、单行尺寸和组合后的无障碍树。
