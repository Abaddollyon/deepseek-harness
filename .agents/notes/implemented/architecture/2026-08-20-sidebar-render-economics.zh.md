# Agent Note: Sidebar render economics under a thousand rows

Status: implemented

[English](2026-08-20-sidebar-render-economics.md) | 中文

## 问题

侧边栏几乎因任何事情都会重新渲染自身。

其行组件订阅了整个会话列表状态，因此任何位置的变化都会重新渲染每一行。拖拽悬停状态保存在共享拖拽状态中，因此指针横跨列表移动时会改变每一行的 props，而不是只改变涉及的两行。分组派生没有缓存，每次渲染都会重新运行。指针移动处理器还会在每个移动事件中调用 `getBoundingClientRect()` 测量列——拖拽期间每个鼠标采样都会强制同步布局。

## 决策

**缩小订阅范围。** 工作区消费者通过针对记忆化目录对象的独立窄选择器读取 ids、byId、current 和 phase，而不是订阅整个状态。

**记忆化行。** `ProjectRowItem`、`SearchResultItem` 和 `SessionNodeItem` 使用带有显式比较器的 `React.memo`。会话比较器有意将时间视为相等，只要它们显示为相同的相对单位和计数；因此不会改变可见内容的时钟刻度也不会改变渲染结果。

**将拖拽悬停限制在拥有它的行。** `RowDragProps` 暴露 `hover(half)`/`clear`，`SessionNodeItem` 自己拥有拖拽标记；父级持有 refs 和记忆化映射，工作区悬停使用命令式 class 标记。指针跨过列表时，现在只重新渲染离开的行和进入的行。

**缓存几何信息，并在使其移动的边缘事件上刷新。** 列矩形保存在 ref 中，并在挂载、resize、`ResizeObserver`、pointerdown 和 pointerenter 时刷新；`pointermove` 读取缓存。代码明确说明，测试针对的是列的**框，而不是 DOM 包含关系**，这正是缓存矩形足够的原因。

**复用派生树。** `deriveGroups` 接收目录的窄 `Pick`，并保留一个单项身份缓存，因此相同的窄输入会返回相同的派生结果。

## 备选方案

**将侧边栏列表虚拟化。** 本次变更拒绝：测得的成本来自每次渲染的扇出，而不是每行挂载；带窄选择器的记忆化行无需承担窗口化的滚动恢复和测量义务即可消除该成本。如果行的*数量*而非更新*频率*成为上限，仍可采用虚拟化。

**拖拽期间在 rAF 中重新计算矩形，而不是缓存。** 拒绝：这会把每次移动一次强制布局换成每帧一次强制布局，同时对于 ResizeObserver 已经精确报告的调整仍然不正确。

**为 `deriveGroups` 使用通用记忆化缓存。** 拒绝：访问模式是一个活动目录，因此单项身份缓存能命中 LRU 的所有情况，且没有需要处理错误的淘汰策略。

## 影响

现在悬停和选择的成本是两次行渲染，而不是一次列表渲染。按照设计，缓存矩形会在刷新边缘之间过时——这是可接受的，因为这些边缘正是移动列的事件，并且 `ResizeObserver` 被视为可选，所以组件没有它也能工作。树缓存是模块级单项缓存，因此它按模块实例共享而不是按组件共享；其正确性完全依赖运行时现在保持稳定的窄输入身份。
