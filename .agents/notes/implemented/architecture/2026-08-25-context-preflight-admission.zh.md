# Agent Note: 规范请求预检在分派前准入压缩

Status: implemented

[English](2026-08-25-context-preflight-admission.md) | 中文

## 问题

自动压缩在 `agent/pre-step` 观测压力，此时循环尚未解析即将发送请求的路由、适配器默认值、上下文容量、系统提示词和工具。路由或提示词变化可能使组装后的请求在压力检查之后才超过容量。恢复只能依赖提供方拒绝后进入 `agent/request-error`，既增加延迟，也无法保护本身就大于所选模型容量的摘要回放。

重试机制还需要比日志增长更强的证据。失败的压缩标记对和无关持久事件都会推进会话日志，却不会缩减模型历史。把这些事件当作重试依据会造成无效循环；而为强制准入而丢弃历史，则违反会话日志作为模型可见上下文持久来源的职责。

## 决策

Agent loop 在准备精确适配器路由并追加规范 `request/header` 与 `request/context` 之后、派生请求消息之前，公开 `agent/request-preflight` waterfall。payload 携带冻结的规范 header、适配器公布时的已解析上下文容量、请求坐标、取消信号和从一开始计数的尝试坐标。waterfall 监听器通过 `next()` 委托；提交替换表层的监听器可以返回 `{ kind: 'retry', surfaceGeneration }`，以便基于持久替换重新执行准入。

只有返回的 generation 等于当前 `session.surface.replaceGeneration` 且比前一轮准入更新时，循环才接受重试。仅日志变化和陈旧 generation 会直接失败。循环把八次有效执行设为固定的防止热循环不变量。达到上限后，它会准入完整持久表层而不是截断内容，使提供方确认的溢出和 `agent/request-error` 恢复仍然可达。

Compaction-basic 是首个消费者。它根据预检 header 中的精确提供方和模型解析策略，计量已记录 envelope 与表层，并依据已配置压力或请求加输出的总容量判定是否符合条件。每次准入最多使用 `maxOverflowRetries` 次替换尝试。可选工具结果剪枝只在压力符合条件后运行；任何替换进展都会触发重新分派，即使后续摘要失败也是如此。

自动摘要之前，compaction-basic 会解析实际摘要模型容量。它会构造摘要目标的精确请求 header，并通过该 header 对回放节点以及规范系统与工具 envelope 计价，同时为已配置摘要输出上限预留空间、计量末尾压缩指令，再把所选平衡头部范围限制在剩余回放输入预算内。如果最小平衡范围仍无法容纳，或容量不可用，它不会发起摘要调用，而是以完整持久请求继续委托。每条完成的助手消息都会结束当前请求的准入预算；即使其工具调用让同一轮次继续进入另一个请求，也是如此。提供方溢出监听器保留为独立后备，并拥有自己的重试序列。

## 结果

路由、提示词、工具或历史变化后的第一个请求，会基于提供方将收到的同一份规范 header 接受检查。成功替换会在派生消息前由完整 waterfall 重新计量，因此下游监听器看到的是已准入状态。持久源事件仍留在仅追加日志中；压缩只通过显式替换事件改变派生表层。

容量未知时，主动摘要会以封闭方式失败，但请求仍可到达能够报告规范溢出的提供方。若已配置摘要输出上限大于摘要模型的可用窗口，系统会阻止自动回放，而不会发出必然无效的辅助请求。部署把 `maxOverflowRetries` 设为 `0` 时，会禁用主动替换重试和提供方溢出替换重试，但仍保留手动压缩。

## 考虑过的替代方案

- **在 `agent/pre-step` 保留压力检查**——拒绝，因为检查无法看到精确路由、适配器默认值、规范 header 或已解析容量。
- **以会话事件数量作为重试证据**——拒绝，因为失败标记和无关事件不能证明模型历史已被替换。
- **只由各插件拥有重试上限**——拒绝，因为一个有缺陷的监听器就能让核心循环无限运行。
- **在准入时裁剪派生消息**——拒绝，因为这会静默移除持久的模型可见历史，并让回放、持久化和提供方行为产生分歧。
- **替换提供方溢出恢复**——拒绝，因为适配器容量元数据可能缺失或不精确；提供方确认路径仍是权威后备。

## 验证

聚焦 agent-loop 测试覆盖顺序、冻结 header、权威 generation 证据、重新分派、替换后派生和核心上限。压缩循环测试覆盖分派前的精确请求压力、具有全新准入预算的公开真实循环工具调用续接、摘要目标 header 计价、平衡替换范围，以及抛出式和带内提供方溢出恢复的保留。跨路由适配器测试证明图片数量上限按路由保持隔离。仓库 typecheck、lint、双语文档门禁、精确运行时覆盖率和聚焦测试套件验证完整组装后的改动。
