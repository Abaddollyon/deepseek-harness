# Agent Note: 自有快照工作区根目录

Status: implemented

[English](2026-08-26-owned-snapshot-workspace-roots.md) | 中文

## 问题

快照、Loader 与 SDK 子进程 harness 每次运行都生成新的 cwd，Web scaffold 每次进程内启动也生成新的 cwd。产品指令与技能发现会从会话 cwd 向上走到最近的 `.git` 标记，因此生成的 cwd 会继承宿主布局恰好提供的任何带标记祖先：位于其上方的主 checkout 或相邻 worktree 可能把 `AGENTS.md` 指令与项目技能贡献进模型可见状态。已记录会话的回放随之依赖开发者的 checkout 布局，同一场景在不同机器上可能组合出不同的请求。DSH 主目录、profile patch、会话持久化与 spill 根目录此前已固定在 harness 自有路径下；项目根发现是剩余未固定的输入。

## 决策

快照与 Loader 子进程 harness 在启动前用空的 `.git` 标记目录把每个生成的 cwd 锚定为自己的项目根；Web scaffold 与 SDK 快照通道对其生成的 workspace 使用相同标记。标记缺失时创建、已是真实目录时保留，而符号链接或文件标记会立即报错，而不是别名外来项目状态。这样项目指令与技能发现会停在所属 cwd，不会让上方带标记的主 checkout 或相邻 worktree 提供模型可见文件。DSH 主目录、profile patch、会话持久化与 spill 根目录仍位于 harness 自有路径中；捕获的 workspace 状态排除 harness 自有的标记，因此提交的期望树无需包含 Git 无法跟踪的条目。

## 取代检查

活动的 workspace-context 备注（2026-06-24）仍是产品根目录发现与标记语义的权威；本备注把该机制应用到测试自有根目录。已检查 2026-08-25 的历史隔离变更以了解意图，但由于快照表面已重命名并重构，不将其作为实现来源。没有活动备注被完全取代。

## 考虑过的替代方案

**让生成的根目录不带标记。** 否决，因为回放密封性随之依赖宿主的临时目录布局以及开发者是否在带标记的 checkout 内运行套件；其失败形态是模型可见输入的静默分歧，而非响亮错误。

**检测到带标记祖先即让运行失败。** 否决，因为这会惩罚合理的宿主布局，而不是让其变得无关；harness 拥有该 cwd，可以确定性地锚定发现。

**静默替换冲突标记。** 否决，因为刚准备好的 cwd 中出现符号链接或文件形态的 `.git` 意味着 workspace 准备放置了 harness 无法说明的状态；替换它会掩盖该缺陷。配置错误必须立即报错。

**让标记不出现在 agent 的目录列表中。** 否决，因为标记真实存在于 cwd 中；对 agent 隐藏它却对发现保留它会让记录的模型可见输出失真。捕获的 workspace 状态改为排除它，与其他 harness 自有的根条目一致。

## 影响

回放组合不再依赖宿主 checkout 布局：每个生成的根目录只发现自己种植的指令与技能。agent 自身的目录列表会显示 `.git` 标记，因此固定根目录列表的期望输出要写出它；捕获的初始与最终 workspace 状态排除它，因此 `workspace.expected` 比较无需 Git 无法跟踪的条目。workspace 准备放置冲突标记条目的场景会在启动前失败并指明冲突。SDK 通道获得了与 ACP、headless、Loader 及 Web scaffold 通道相同的锚定与排除。

## 测试

Loader 冒烟测试在两个真实临时根目录中执行，断言每个子进程 cwd 与标记，并断言根目录不同；针对性单元测试覆盖标记创建、对既有真实标记目录的容忍，以及对符号链接与文件标记的拒绝。快照 harness 测试固定标记在 agent 自身目录列表中的存在及其在捕获 workspace 状态中的缺席。针对性的快照与 Loader 测试覆盖执行路径，而非计划文本。
