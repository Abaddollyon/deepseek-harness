# Agent Note: 折叠的 Workspace 分组保留运行中的 Session

Status: implemented

[English](2026-08-19-collapsed-groups-pin-running-sessions.md) | 中文

## 问题

侧边栏的 Workspace 分组默认关闭，而关闭之后完全不渲染任何 Session 行。因此，只要分组被折叠，仍在运行的 Session 就会立刻从侧边栏消失，而折叠正是侧边栏的常态。用户既失去了进度信号，也失去了返回 agent 正在进行的工作的入口，并且没有任何迹象表明有内容被隐藏。限制分组高度属于显示层面的诉求，不应决定哪些进行中的工作还能被触达。

## 决策

`GroupNode` 在 `sessions` 之外新增第二个行数组 `pinned`。`deriveGroups` 一次性构建分组的行，再按展开状态拆分：展开的分组把全部行放入 `sessions` 并让 `pinned` 为空；折叠的分组让 `sessions` 为空，并把其中进行中的行放入 `pinned`，保持它们在分组内的顺序。行为「进行中」的判定是：自身正在运行，或 `runningSubagentCount` 大于零——即经不间断的 subagent 谱系可达的运行中后代数量。已完成但未查看的提醒（`completed`）属于已结束状态，与空闲行一同折叠隐藏。

两个数组互斥，因此任何 Session 都不会渲染两次，而折叠的分组保持现有的「`sessions` 中没有行」约定——拖拽、重排序和溢出路径读取的正是这一点。这些路径未作改动：保留行不带拖拽接线，因此重排序永远不会以其为目标；`COLLAPSED_SESSION_LIMIT` 仍然只对 `sessions` 做切片与计数，因此折叠期间**展开其余**控件始终不出现，其余量算术也始终忠实于展开列表。

推导是对实时 `useSessions` 快照的纯 `useMemo`，因此保留集合随活动变化而无需另设可能过期的状态：开始运行的 Session 会出现在其折叠的组头之下，停止运行的 Session 会在同一次推导中移除。

### 呈现

带有进行中工作的折叠分组不得读起来像展开的分组。组头保持关闭的文件夹图标、未旋转的箭头以及 `aria-expanded="false"`——该分组确实处于折叠状态，而保留行是同一扁平树中的同级 `treeitem` 行，而非被展开的子节点，因此该属性对辅助技术仍然准确。保留行采用树的 22px 缩进步长置于其组头之下。当折叠仍隐藏着保留行之外的 Session 时，分组通过 `sessions.hiddenIdle` 字典条目按 `sessionCount - pinned.length` 打印其数量，使可见行不会被误认为分组的全部。

### 不设配置项

这是唯一正确的行为，而非随部署而变的策略，因此不附带 `Config` 字段。浏览器半侧的 `Config` 今天也是失效的：`WebBootEntry` 只携带 `id`、`url`、`rev`、`inject` 和 `immediately`，且 web 启动路径创建条目时不传配置，因此 client 插件根本无法接收 cordis.yml 配置。

## 备选方案

**只保留一个 `sessions` 数组，折叠时在渲染器中过滤。** 折叠的分组仍会在数组中报告行，而拖拽、重排序和溢出切片都读取该数组，于是每一条路径都需要各自的排除规则，每一处都可能把计数弄错。

**让保留行与展开行渲染一致。** 若某折叠分组的 Session 恰好全部在运行，它将与展开分组画得一模一样，折叠状态变得无法辨认，组头切换的结果也无法预期。

**因为有行可见就报告 `aria-expanded="true"`。** 辅助技术会把折叠分组播报为展开，并暗示其余 Session 也在场。这些行是扁平树中的同级项而非被展开的子节点，因此诚实的取值是 `false`。

**把存在待处理用户交互的行也保留下来。** 等待审批是应由组头聚合的状态，而不是把某一行强推出折叠之外的理由；把「进行中」判定扩展到它，应与那个尚不存在的组头指示一并落地。该项仍列为已知限制。

**保留已完成但未查看的提醒。** 已完成的 Session 属于已结束状态，保留它会让每个折叠分组不断累积行，直到逐个打开为止——这恰恰是折叠机制要解决的高度问题。

**新增 `pinRunningSessions` 配置字段。** 隐藏进行中工作的部署既无属主也无依据；仓库要求公开选择必须有当前消费者，而 client 插件今天也无法从 cordis.yml 配置。

## 影响

- 折叠限制分组高度，但不再决定哪些内容可被触达：进行中的工作在每次折叠后依然存在，已结束的工作则不会。
- `GroupNode` 新增必填字段 `pinned`，因此所有构造点——包括构建分组字面量的测试——都要提供它。
- 拖拽、重排序和溢出逻辑保持不变，因为折叠的分组仍然不暴露 `sessions`。
- 带有进行中工作的折叠分组比以往占用更多垂直空间，其上界即该分组自身运行中的 Session 数量。
- 仅有待处理用户交互仍无法穿透折叠；应当持有该行为的组头聚合尚未构建。

## 测试

`tree.client.spec.ts` 覆盖 `pinned` 与 `sessions` 的互斥、自身活动与运行中后代两种保留来源、`completed` 行的排除，以及连续推导之间「运行转空闲」和「空闲转运行」的切换。`rows.client.spec.tsx` 覆盖保留行渲染期间折叠组头仍报告 `aria-expanded="false"` 并保持关闭的文件夹与未旋转箭头，以及保留行是缩进且不可拖拽的 `treeitem`。`workspace-browser.client.spec.tsx` 覆盖组装后的分组：折叠期间进行中的行可达、隐藏余量计数、折叠期间不出现溢出控件、展开后余量算术保持不变、两个数组之间不出现重复行，以及保留行在其运行结束时离开。

## 相关
