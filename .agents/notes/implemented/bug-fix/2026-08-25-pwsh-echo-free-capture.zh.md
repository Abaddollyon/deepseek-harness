# Agent Note：容忍 PowerShell 输入回显的物理折行

状态：已实现

[English](2026-08-25-pwsh-echo-free-capture.md) | 中文

## 问题

`tool-pwsh-persistent` 通过真实 PTY 提交带 marker 的包装器。PowerShell 的交互式行编辑器会先把该输入渲染回终端流，随后包装器才输出真实的 START marker、命令输出和 END 状态。短命令的包装器已经超过配置的 160 列终端，而包装器还嵌入模型命令，因此任何固定宽度都不充分。终端插入的物理换行会使单行包装器精确替换失效，并可能让回显中的 marker 看起来像命令进度。

直接 PTY 实验否定了“移除 PSReadLine 即可消除回显”的假设。`Remove-Module PSReadLine` 使 `Get-Module PSReadLine` 返回 false，但后续输入仍会被渲染。使用 `-NonInteractive` 启动时也一样，包括启动命令确认没有 PSReadLine 模块可移除的路径。PowerShell 宿主的行读取器在没有该模块时仍具交互行为，因此必须保留回显处理。

真实 shell 还暴露了两个相关的就绪缺陷。pwsh 后端会在原生提示符就绪前提交编码和提示符引导；若早期静默结算返回空 viewport，代码还会把空 viewport 当作“首次发送”标记而再次提交引导。回显的引导源码包含受控提示符字面量，因此子串搜索会把源码误认成就绪。当当前 operation 没有产生 delta 时，提示符回退还可能错误代入历史 viewport 文本。

## 决策

捕获最多移除一次精确提交的包装器，并允许其源码字符之间出现 CR 与 LF。匹配器建立去换行投影及原始偏移表，在投影中查找精确包装器，再从原始文本中移除对应区间。真实命令输出的换行保持不变。完整 marker 提取、快照回退与增量回退都在清理后的文本上运行。若包装器在捕获前已被裁掉一部分，系统不会猜测片段，而是保留无法匹配的内容并明确标记结果不完整。

提示符回退只使用当前 operation 的 send 输出；当本次 send 没有 delta 时，不再用终端历史 viewport 替代。当前包装器的折行回显后若紧跟过期就绪，清理后会得到空的不完整捕获，因此轮询会继续，直到出现当前 marker 或诊断证据。累计回退由已提交包装器、配置的输出上限和受控提示符长度共同限制。模型重定义 `prompt` 仍会移除自有 marker，并使用既有的较慢静默档。

pwsh 终端方言先等待启动就绪，只发送一次 UTF-8 与受控提示符引导，然后用不含输出的后续 send 观察，直到受控提示符确实位于保留输出的尾部或启动超时。会话存活期间，行式 PTY 用稳定原点响应光标位置查询，使 PowerShell 行编辑器无需屏幕模型也能完成渲染；咨询性质的响应若被拒绝，不会导致会话失败。静默档仍可结算不产生输出的 send，而 PowerShell 输出会获得配置的前台交接宽限以完成行编辑器渲染。

单元覆盖保留单行回显用例，并增加 LF 与 CRLF 折行回显、折行提示符回退、只有回显的过期就绪、拆分光标查询及被拒绝响应、延迟单次引导、启动 deadline、静默输入就绪和 PowerShell 渲染宽限用例。安装 pwsh 后，真实 shell 覆盖验证持久状态与 UTF-8 输出。

## 已考虑的替代方案

**启动后移除 PSReadLine。** 直接 PTY 证据表明卸载模块不会移除宿主的输入渲染，因此拒绝。

**不加载 PSReadLine 启动 PowerShell。** `-NonInteractive` 以及启动时没有已加载 PSReadLine 模块的路径仍会在 PTY 中渲染输入，因此拒绝。

**增加终端宽度。** 包装器包含模型命令，任何有限宽度都无法阻止所有折行，因此拒绝。

**提取前折叠所有换行。** 命令输出拥有自身行结构，因此拒绝。只有精确、含 nonce 的包装器匹配可以忽略物理换行，返回文本仍是仅移除该原始区间的原始流。

**引导期间接受任意受控提示符子串。** 提交的提示符函数源码在执行前就包含该字面量，因此拒绝。

## 影响

持久 PowerShell 命令不再依赖终端宽度，延迟的行编辑器渲染也无法触发第二次引导，或让上一条命令的 marker 结束新命令。输入回显仍是已记录的平台事实，而不是可移除的限制。若有界回滚区丢弃了回显包装器的一部分，不完整结果可能保留无法匹配的片段并报告裁剪。PTY 仍提供行式输出而非完整终端仿真；光标响应只用于满足交互式行读取器。
