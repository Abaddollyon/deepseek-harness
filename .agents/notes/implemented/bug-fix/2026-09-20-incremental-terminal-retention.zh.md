# Agent Note：回移增量终端输出保留

Status: implemented

[English](2026-09-20-incremental-terminal-retention.md) | 中文

## 问题

原终端缓冲区将每次回调追加到同一个保留字符串，再为行数上限拆分、为 UTF-8 上限重新扫描。小回调反复处理整个保留窗口，同时影响持久 scrollback 和活动发送输出，而输出上限并未变化。

## 决策

将上游 `cea837e06525384855e3b8b8231c2400bc3cb85b` 适配到 [session.ts](../../../../packages/terminal/terminal-bash/src/session.ts) 的私有缓冲区，不迁移终端所有权、沙箱或侧边栏。使用链式字符串块累计字节数和换行数，将小回调合并到最多 4096 个 UTF-16 单元；封存块时保留孤立代理项，只有丢弃至少一半底层字符串后才复制剩余后缀。跨块的相邻代理对采用一致计数。snapshot 和 consume 仍组装保留文本；consume 重置截断标记和计数器。

## 考虑过的替代方案

- 继续扫描整个保留字符串：有界内存并不限制累计追加工作量。
- 每次回调一个节点：微小写入会让元数据随回调数量增长。
- 存储 UTF-8 编码块：编码会改变孤立代理项语义。
- 导入整个终端/侧边栏迁移或基准打包改动：私有实现修复不需要这些变化，还可能影响分支的所有权约定。

## 验证

[缓冲区回归](../../../../packages/terminal/terminal-bash/tests/session-buffer.spec.ts) 将公开读取和发送增量与原算法参考实现比较，覆盖 4 MiB 上限、行数/字节上限、拆分 Unicode、合并边界及 consume/reset。确定性计数工作量测试追加 2000 个 32 字符块，拒绝反复扫描保留历史：旧实现处理 64,032,000 个字符单元，超过 128,000 上限。这是算法负对照，不是真实 shell 延迟测量。[会话回归](../../../../packages/terminal/terminal-bash/tests/session.spec.ts) 保留就绪、取消与关闭覆盖。

## 后果

追加计数和淘汰的工作量摊销到新增/丢弃文本。读取仍分配并检查保留窗口；频繁读取的消费者仍可能较昂贵。工具 schema、默认上限、权限和对外生命周期均不变化。
