# Agent Note: 会话列表与导航恢复

Status: implemented

[English](2026-09-13-session-list-and-navigation-recovery.md) | 中文

## Problem

重叠的会话列表请求会重复观测冷标题，并在另一次观测替换缓存条目时丢弃有用结果。将标题观测拆分为每次十六个会话的调用，还会在每次调用中重复列举全部持久化数据。高负载下，这些后台工作会与历史、工作区流和命令争用资源。

subagent 列表行可能先于其直接父会话目录到达。仅凭会话 id 打开该行会违反历史控制器的持久地址要求。延迟的工作区变更响应可能覆盖更新的流状态，包括毫秒时间戳相同的行。模型选择调用被拒绝后，其控件可能永久保持忙碌。

## Decision

列表控制器在启动一次查询观测前预留未缓存的标题。查询提供方负责限制并发持久化读取，并在投影后释放每份完整日志。重叠的列表请求共享预留；取消和失败会释放预留，供后续重试使用。缓存身份继续阻止生命周期替换和陈旧完成结果的干扰。

subagent 导航在发布当前子会话前解析直接父会话目录。待处理导航遵循用户后续选择和子会话移除。工作区变更回声受期间到达的流或基线更新约束。模型选择调用被拒绝时会解除忙碌状态，并阻止旧代次改变当前控件。

## Alternatives considered

增加重连超时无法消除重复的历史读取和陈旧状态竞态。把子会话作为普通会话打开会削弱持久父地址要求。保留每次十六个会话的标题调用可以较早发布部分标题，但会重复列举整个数据集；单次观测保留提供方的读取上限，并省去这些额外列举。持久标题索引可以进一步减少冷启动工作，但需要独立设计失效和存储机制。

## Consequences

标题在预留的观测完成后发布，因此一份缓慢的历史可能延迟该观测中的标题；会话行仍可独立使用。重复调用仍执行各自的权威列表读取。定向回归覆盖七个重叠列表请求、64 份冷历史的有界读取、重试和生命周期取消、subagent 导航、工作区流竞态，以及被拒绝的模型选择。合成历史计数并不代表在线提供方吞吐量或同时执行 50 个模型任务的容量。
