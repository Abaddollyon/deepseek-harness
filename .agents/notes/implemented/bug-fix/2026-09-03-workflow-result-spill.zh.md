# Agent Note：超大工作流结果保持可恢复

状态：已实现

[English](2026-09-03-workflow-result-spill.md) | 中文

## 问题

某个工作流脚本返回了一个包含 22 项的 JSON 对象，其序列化结果超过工具默认的 50,000 字符上限。工具恰好在上限处从字符串中间切断该值，却没有截断标记、原始长度说明或 spill 路径。持久任务记录保存了同一个受限残片，因此除非 worker 碰巧另行写入文件，否则成功结果无法恢复。

## 决策

工作流工具会在投影完成返回值之前先将其序列化。超过 `maxResultChars` 时，工具通过会话范围的 `ctx.spillStore` 保存精确完整的 JSON，并将结果值替换为 `{ truncated: true, originalChars, spillPath, preview }`。若没有 spill 后端可以保存超大值，工具会明确失败，而不会展示一个看似成功但已损坏的结果。

由 supervisor 所有的任务会在结算前使用同一投影。本地持久任务注册表识别该工作流标记；如果自身的字节上限更小，它只缩短 `preview`，同时保留原始字符数与 spill 引用。

## Alternatives considered

**继续截断并添加文本后缀。** 拒绝，因为后缀虽能指出数据丢失，却不能恢复结构化数据，而且在第二层持久输出上限下，后缀本身也可能消失。

**仅在持久任务 store 中保存完整结果。** 拒绝，因为 caller 所有的工作流运行同样需要恢复约定，任务 store 仍有上限，而且 spill 服务已经拥有会话 artifact 的目录策略与生命周期。

**添加宿主接线或工作流专用 artifact 目录。** 拒绝，因为所属插件可以使用现有 Cordis spill seam；第二套路径策略会让通用工作流工具耦合到某个部署。

## 验证

工作流包测试返回超过 50,000 字符的结构化值，验证标记的每个字段，读取 `spillPath`，并将其字节与精确完整的格式化 JSON 比较。supervisor 工作流测试验证持久记录保留标记和可读引用。jobs-local 测试还会强制使用更小的持久字节上限，并验证恢复元数据保留、只有预览缩短。

## 结果

无论前台模式还是 supervisor 模式，大型成功工作流结果都可恢复，模型也会从工具描述中获知该约定。超大结果的完成现在依赖已挂载的 spill 后端；存储缺失或失败会显示为错误，而不再静默丢失数据。持久标记元数据的优先级高于预览文本。
