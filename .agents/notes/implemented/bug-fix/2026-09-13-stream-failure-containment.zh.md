# Agent Note: 流故障隔离与显式读取恢复

Status: implemented

[English](2026-09-13-stream-failure-containment.md) | 中文

## Problem

异步提供商、子进程和 JSON-RPC 故障可能逃离负责该操作的调用方。断开的工作区订阅也可能耗尽传输重试，使用户无法使用有效的重试操作。

## Decision

提供商流的创建和消费使用同一错误转换。被拒绝的 Codex 响应锚点保留其传输分类。子进程收集隔离落盘文件故障，保留有界输出尾部，并报告 `spillFailure`，使调用方能够区分持久化不完整与完整输出。

JSON-RPC 终止性写入错误会结束待处理请求并终止连接。延迟的入站处理器不能在关闭后写入，而对端半关闭仍允许已接受的请求收到响应。

工作区订阅将耗尽重试的远程流载体识别为可重试的读取故障。显式重试操作启动一个新订阅，并合并重复点击。终止性 Host 错误保持终止状态；此恢复从不重放命令。

CI 运行器使用已访问 PID 集合和逐项队列插入来遍历采样进程表。重复行和过期的循环父子关系不会重复进程、将根进程列为其后代，或在快速失败进程采样期间使参数栈溢出。

## Alternatives considered

**仅捕获最初的提供商调用。** 流故障可能在调用返回后的消费期间发生，因此这种做法无法覆盖异步错误。

**将所有网关错误视为可重试。** 这会掩盖终止性 Host 故障，并可能促使重放具有副作用的操作。恢复仅限于已识别的读取载体故障。

**持久化失败时使子进程收集失败。** 这会丢弃有用的有界输出，并使文件系统故障逃离进程清理。显式的持久化不完整元数据为调用方保留了这种区别。

## Consequences

故障通过操作结果保持可见，而不会成为未处理的拒绝。部分子进程输出带有明确的持久化故障。自动重试耗尽后，读取恢复需要用户操作；持续的传输中断仍可能导致恢复失败。

提供商、子进程、JSON-RPC 和工作区订阅的定向回归测试覆盖错误归属、关闭顺序、有界输出以及显式重试合并。Host 和客户端类型检查及官方构建验证集成。
