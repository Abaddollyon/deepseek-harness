# Agent Note: 窄视口 Settings 布局

Status: implemented

[English](2026-09-05-narrow-settings-layout.md) | 中文

## Problem

Settings 面板在窄视口中仍把 188px 的桌面导航栏放在内容旁。扣除面板边距与内容内边距后，390px 视口只为每个 Settings 分区留下约 106px。即使面板本身没有超出视口，模型控件、委派配置与自动化表单仍会被裁切或挤压。

## Decision

视口宽度不超过 640px 时，Settings 面板使用单列。标题与分区按钮组成紧凑的水平导航行，位于标题栏及当前分区上方。当贡献的分区超出可用宽度时，该行可以水平滚动；当前分区仍使用面板内的垂直滚动区域。面板与视口保持 12px 间距，标题栏中的配置操作与关闭控件位于同一有界列内。

桌面声明仍为默认值：800px 面板及内容旁 188px 的导航栏。此响应式修复只改变呈现；分区注册、选择状态、设置值与焦点行为仍由既有外壳和功能组件持有。

## Alternatives considered

**缩窄内容旁的桌面导航栏。** 更窄的导航栏仍占用宝贵的水平空间，并同时截断导航和功能控件；随着贡献分区数量增加，它也会愈发脆弱。

**在窄视口中让面板全屏显示。** 全屏接管可以提供更多空间，但会丢失既有模态上下文，并造成超出缺陷修复所需的视觉层级变化。

**把分区标签隐藏到菜单中。** 菜单可以节省空间，但会降低分区发现与切换的直接性，并为纯呈现修复引入新的状态和交互行为。

## Consequences

每个贡献分区仍显示为带标签的按钮，并可按文档顺序通过键盘到达。较长的导航集合以水平滚动换取无法同时展示全部项目。当前分区获得明显更宽的内容区域；很高的内容仍在有界面板内滚动，而不会移动其后的页面。

## Testing

包内样式契约固定窄视口断点、单列面板、水平导航溢出、垂直内容滚动及未变的桌面尺寸。拼装后的 Settings Chrome 浏览器场景在窄视口中验证面板边界、上下堆叠布局、配合 `aria-current` 的真实键盘分区切换、可达的标题栏控件、内容溢出、Escape 关闭、触发控件焦点恢复与安静的控制台。既有桌面 ARIA 基准保持不变。
