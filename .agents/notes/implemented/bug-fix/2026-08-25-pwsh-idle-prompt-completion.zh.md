# Agent Note：空闲的 pwsh 提示符并不代表命令完成

Status: implemented

[English](2026-08-25-pwsh-idle-prompt-completion.md) | 中文

## 问题

持久化 pwsh 工具轮询 PTY，并把空闲的 shell 提示符当作命令已完成的证据。这一推断在某个时刻是错误的：刚启动的 shell 在尚未回显任何刚发送的命令之前，同样停在空闲提示符上。在该窗口内进入 `promptCompleted` 会产生一个没有文本且 `incomplete: true` 的捕获，而 `maybeTruncate` 会把它渲染为仅有的截断提示。模型被告知结果已被截断，然而当时并不存在可截断的输出；它收到的提示还建议用 `Select-String` 搜索文件——对任意命令输出而言毫无意义。

该竞态需要较慢的启动才会出现，因此从未在开发机上暴露。它在本地测试中同样不出现，原因更简单：涉及真实 shell 的用例在未安装 `pwsh` 时会跳过，而通常运行该套件的机器并未安装。托管的 fork CI 门禁运行在自带 PowerShell 的镜像上，首次执行即告失败。

## 决定

只有当捕获有内容可报告时，空闲提示符才被接受为完成：文本非空，或捕获已标记为完整。空且不完整则继续轮询，现有的命令超时仍是上界，因此真正永不应答的 shell 仍会以超时失败，而不是以错误结果收场。

提示符回退本身予以保留。它负责报告前缀已滚出保留缓冲区的结果——此时起始标记确实缺失但存在真实输出；该情形带有文本，不受影响。改为要求起始标记会删除这一回退：它会破坏缺失前缀与滚动缓冲耗尽的用例，而这正是两种情形边界的定位方式。

## 备选方案

**等待完成标记并去掉提示符回退。** 否决：回退用于起始标记已离开保留缓冲区的捕获。移除它会把这些结果变成超时，本包自身的缺失前缀与滚动缓冲耗尽用例即为证明。

**在接受空闲提示符前要求起始标记。** 基于同样理由否决，并已通过运行套件确认：两个基于 mock 的回退用例会挂起直到测试超时。

**提高轮询间隔或命令超时。** 否决：两者都是用时序掩盖竞态而非消除它，且都无法让空捕获成为真实结果。

## 验证

`packages/shell/tool-pwsh-persistent/tests/tools.spec.ts` 以 mock 后端覆盖该边界：缺失前缀、滚动缓冲耗尽与提示符回退用例仍经由回退完成，而启动窗口不再把空捕获渲染为截断输出。

## 影响

驱动持久化 shell 的模型不再为从未产生的输出收到截断提示，因而不会再按该提示的文件搜索建议走上无益的路径。确实没有产生任何输出的 shell 现在会到达超时并报告超时，这陈述的是真实状况。
